# Help build the Accessibility Knowledge Base

Help build the [WP Accessibility Knowledge Base](https://wpaccessibility.org/), the WordPress community's accessibility documentation. Pick one way to contribute: write or update a page, review a draft someone else wrote, or report an error you find.

- **Reference:** [How to contribute](https://wpaccessibility.org/docs/about/contribute/)
- **Connect:** Join [#accessibility-docs](https://wordpress.slack.com/archives/accessibility-docs) on Slack and introduce yourself

## Steps

1. **Explore.** Check the [WP A11y docs project board](https://github.com/orgs/wpaccessibility/projects/3) and [wpaccessibility.org](https://wpaccessibility.org/) to see what exists and what's still needed.

2. **Pick one way to contribute.**
   - **Write or update a page.** Contact the team and wait until the task is assigned to you. Content written without that assignment will not be reviewed. An assigned update to an existing page uses this same path. Follow [Write documentation](https://wpaccessibility.org/docs/about/contribute/write/).
   - **Review a draft.** Find open work in the project board column "PRs to review". Review only the new content in that pull request. You can start without an assignment. If an existing page looks wrong, report that as an error instead. Follow [Review documentation](https://wpaccessibility.org/docs/about/contribute/review/).
   - **Report an error.** You can start without an assignment. Follow [Report an error](https://wpaccessibility.org/docs/about/contribute/report-error/). Use this for the Knowledge Base and for wpaccessibility.org. An accessibility bug in WordPress itself goes on [Core Trac](https://core.trac.wordpress.org/newticket), with the focus set to accessibility.

3. **Follow the page you chose.** For a new or updated page, write in your own words, follow that page's structure, and use AI only to translate or to check your English. For a review, respond to the new content in the pull request. For an error report, include enough detail for the team to investigate.

4. **Share the result.**
   - **Page:** use the [contact form](https://make.wordpress.org/accessibility/accessibility-knowledge-base-contact/), [#accessibility-docs](https://wordpress.slack.com/archives/accessibility-docs), a comment on the related [GitHub issue](https://github.com/wpaccessibility/wp-a11y-docs/issues), or a [pull request](https://wpaccessibility.org/docs/about/contribute/github/pull-requests/).
   - **Review:** comment on the pull request, or use the contact form or [#accessibility-docs](https://wordpress.slack.com/archives/accessibility-docs).
   - **Error:** use the contact form, [#accessibility-docs](https://wordpress.slack.com/archives/accessibility-docs), or open a [GitHub issue](https://github.com/wpaccessibility/wp-a11y-docs/issues).

## Contribution checklist

- For a new or updated page, got the task assigned before writing
- Followed the instructions linked for the path you chose
- Shared a page, a review, or an error report through a channel listed for that path

## What happens next

A new page or a proposed change is reviewed, and it may need edits before it is published. Comments on a draft are read with that pull request. An error report is investigated, and it may become a task for someone else to fix.

If you don't hear back, follow up in [#accessibility-docs](https://wordpress.slack.com/archives/accessibility-docs). When you're ready, pick up another topic or settle into an area you can develop further.

## Help

Stuck? Check the [getting help guide](https://make.wordpress.org/handbook/pathways/before-you-begin/#getting-help), then ask in [#accessibility-docs](https://wordpress.slack.com/archives/accessibility-docs).
